# 模型路由器运行说明

> 状态：首个可运行里程碑
> 版本：v0.1
> 更新日期：2026-08-28

## 已实现能力

- 统一大语言模型请求和流式事件契约。
- Dify 工作流无状态输入映射，每轮显式传入角色、短期上下文和长期记忆。
- 使用 `/workflows/run` 真正逐行读取服务端事件流，不等待完整响应。
- 支持文本增量、完成、失败、暂停和未知事件处理。
- 支持用户取消、停止任务接口和取消后的迟到文本隔离。
- 首个文本增量前最多重试一次；产生文本后禁止重试和拼接。
- 支持首个文本前切换备用模型，并创建新的生成任务标识。
- 指标和链路属性不记录密钥、提示词、记忆及回复正文。

## 调用已部署的 Dify 工作流

先在当前终端安全注入配置，不要把真实密钥写入仓库：

```bash
export DIFY_WORKFLOW_BASE_URL='https://你的服务地址/v1'
export DIFY_WORKFLOW_API_KEY='你的工作流应用密钥'
```

执行一轮无状态调用：

```bash
/Users/yuezhenting/esp/xiaozhi-all/.venv/bin/xiaozhi-dify '今天有点累' \
  --用户标识 '本地验收用户' \
  --角色 '{"name":"幽光","persona":"温暖、自然、不过度说教"}' \
  --短期上下文 '[{"role":"assistant","content":"我在，慢慢说。"}]' \
  --长期记忆 '[{"id":"m_1","content":"用户周五通常工作较忙"}]'
```

命令会逐行输出统一事件。成功时至少包含：开始事件、一个或多个文本增量事件、完成事件。工作流输入变量必须与 [Dify 工作流模型提供方契约](../../docs/03-协议/Dify工作流提供方契约.md)一致。

## 安全要求

- 禁止把真实密钥写入 `.env.example`、测试夹具、日志和命令历史。
- 设备、网页端和移动端不得直接调用 Dify，也不得持有 Dify 密钥。
- Dify 工作流中不得依赖 `conversation_id`；会话和记忆由本项目统一管理。
