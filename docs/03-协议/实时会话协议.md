# 实时会话协议基线

> 状态：基线生效
> 协议版本：v1
> 更新日期：2026-08-28

## 传输

- 控制事件使用 UTF-8 JSON。
- 音频使用 WebSocket Binary Frame，不使用 Base64 JSON。
- 每个二进制帧必须携带固定头：协议版本、类型、序号、时间戳、轮次、生成任务、负载长度。
- 网页端/移动端 的 WebRTC 事件必须映射成相同内部事件语义。

## 必需标识

```json
{
  "protocol_version": 1,
  "session_id": "session_xxx",
  "turn_id": 18,
  "generation_id": 3,
  "event_id": "event_xxx",
  "timestamp_ms": 1787890000000
}
```

## 核心事件

| 方向 | 事件 | 作用 |
| --- | --- | --- |
| 终端→服务 | `session.start` | 协商能力、音频格式和应用版本 |
| 双向 | `session.ready` | 确认连接与恢复游标 |
| 终端→服务 | `audio.input.start` | 用户开始说话 |
| 终端→服务 | Binary audio | 上传连续 Opus 帧 |
| 终端→服务 | `audio.input.end` | 终端明确结束或超时结束 |
| 服务→终端 | `asr.partial` | 增量识别，仅展示不提交历史 |
| 服务→终端 | `asr.final` | 当前用户 Turn 最终文本 |
| 服务→终端 | `assistant.text.delta` | AI 增量文本 |
| 服务→终端 | Binary audio | 当前生成任务的语音合成音频 |
| 服务→终端 | `playback.pause` | 软暂停，等待打断确认 |
| 服务→终端 | `generation.cancel` | 取消指定 Generation |
| 终端→服务 | `playback.progress` | 上报 `played_ms` 和最后音频序号 |
| 双向 | `error` | 可恢复或不可恢复错误 |
| 双向 | `ping/pong` | 心跳与时钟偏差估计 |

## 状态机

```text
DISCONNECTED → CONNECTING → READY
READY → LISTENING → THINKING → SPEAKING → READY
SPEAKING → INTERRUPT_PENDING → LISTENING
INTERRUPT_PENDING → SPEAKING  （误打断恢复）
任意状态 → RECOVERING → READY / CLOSED
```

## 一致性规则

1. `turn_id` 在用户新一轮有效发言时递增。
2. 同一 Turn 重试、重新回答或 Provider 切换时 `generation_id` 递增。
3. 终端只播放当前生成任务，其他迟到帧直接丢弃。
4. 音频序号单调递增；发现缺口时记录指标并按 jitter 策略处理。
5. `event_id` 用于控制事件幂等，断线重发不能重复提交历史或计费。
6. 服务端历史只提交 `played_ms` 对应的 AI 文本范围。

## 兼容

- 新增可选字段保持同一主版本。
- 删除字段、修改语义或二进制头布局必须升级主版本。
- 服务端至少支持当前版本和前一个主版本，并记录终端协议分布。
