# 实施路线图

> 状态：基线生效
> 版本：v0.1
> 更新日期：2026-08-28

## M0：基线与基准工具

- 初始化仓库、CI、配置和本地开发环境。
- 固化实时协议 v1、模型提供方契约和状态机。
- 建立中文陪伴语音测试集、网络仿真和阶段耗时采集器。
- 输出旧系统基准数据，作为优化对照而非代码基线。

退出条件：同一测试可重复产生语音识别、大语言模型、语音合成、首音和打断阶段指标。

## M1：ESP32 真机最小闭环

- Device Gateway 接收 Opus 上行并下发 Opus 音频。
- 语音运行时 完成 会话、轮次、生成任务、背压和取消。
- 接入腾讯实时语音识别、真实 Dify Chatflow 和火山双向流式语音合成。
- 实现真打断、误打断恢复和 `played_ms`。

退出条件：ESP32 达到 P95 首音 1.2 秒、打断 250 毫秒和 30 分钟长稳。

## M2：低成本与可靠性

- 本地 sherpa-onnx 与付费语音识别影子评测。
- 模型提供方主备、熔断、超时、成本路由和固定音频缓存。
- 弱网恢复、断线续会话、迟到帧隔离和容量测试。

退出条件：本地语音识别达到质量门槛后可配置为主用；单模型提供方故障可自动降级。

## M3：网页端与移动端

- 增加 LiveKit RTC Gateway 和客户端 SDK。
- 复用相同 语音运行时、模型提供方和历史提交规则。
- 验证浏览器、iOS、Android 的回声、权限、后台和耳机场景。

退出条件：不同终端的会话语义和指标口径一致。

## M4：陪伴产品能力

- 角色、长期记忆、情绪状态和安全策略。
- 音乐、设置、小游戏的应用框架和音频资源仲裁。
- 控制后台、成本分析和灰度发布。

退出条件：新增应用不修改实时协议核心和模型提供方契约。
