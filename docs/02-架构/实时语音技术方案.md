# 实时语音技术方案

> 状态：基线生效
> 版本：v0.1
> 更新日期：2026-08-28

## 音频基线

- 输入：16kHz、16-bit、单声道 PCM，经 Opus 20ms 帧传输。
- 输出：优先 Opus 16kHz 单声道；模型提供方返回 PCM 时在服务端统一编码。
- MCU 负责采集、AEC、基础降噪、播放参考和 Opus 编解码。
- 服务端维护小型 jitter buffer，不允许无限积压。

## 实时处理链

```text
音频帧 → 解码/抖动缓冲 → VAD → Streaming ASR partial
      → Smart Turn → ASR final → Streaming LLM token
      → 口语化清洗/语义分句 → Bidirectional TTS
      → 音频帧队列 → 终端播放 → played_ms 确认
```

## 对话轮次与打断

1. 用户开始说话时立即发送 `playback.pause`，目标 P95 250ms 内停声。
2. 保留 120 至 200ms 确认窗口，并结合语音识别内容判断是否为真实打断。
3. 真打断取消当前生成任务的大语言模型、语音合成、队列和终端播放。
4. 误打断从最后一次 `played_ms` 恢复，不能从头播放。
5. 被取消生成任务的迟到数据必须丢弃，不能写入历史。

## 模型提供方策略

### 语音识别

- 本地 `sherpa-onnx Streaming Zipformer/Paraformer` 作为低成本候选。
- 付费流式语音识别作为质量基线和低置信度、噪声、多语种回退。
- 是否转为本地主用由统一语料集的 CER、首个 partial、final 延迟和 CPU 成本决定。

### 大语言模型

- 自有 OpenAI-Compatible 流式模型作为主服务。
- Dify、Coze 只能作为模型提供方适配器，不得进入会话核心接口。
- 普通陪聊选择低延迟模型；工具调用和复杂推理按策略升级。

### 语音合成

- 商业化主链路优先使用可追加文本、增量音频、情感音色和取消的双向流式语音合成。
- 同一生成任务保持一条语音合成会话，不按标点重复建连。
- 自部署语音合成仅作为基础音色降级，固定提示音允许缓存。

## 延迟预算

| 阶段 | P95 预算 |
| --- | ---: |
| 轮次 结束判断 | 350ms |
| 大语言模型首字延迟 | 450ms |
| 语音合成首包 | 300ms |
| 下行与终端起播 | 120ms |
| 用户结束到首音 | 1.2s，允许流水线重叠而非简单求和 |

## 资源与成本

- 取消后立即停止模型提供方请求，避免无效词元和音频计费。
- 固定开场白、错误提示和系统提示可缓存编码后音频。
- 对每轮记录语音识别秒数、大语言模型词元、语音合成字符数和实际成本。
- 不为普通对话生成和永久保存 MP3 文件。
