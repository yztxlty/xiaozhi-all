# 幽光状态动图与情绪协议设计

> 状态：已确认  
> 日期：2026-08-29

## 一、目标

将 H5 实时语音通话页现有的 CSS 扁平角色替换为统一、高质感、透明背景的毛绒幽光动图。角色表情必须同时反映实时语音阶段和当前对话情绪，且不得降低拾音、语音播放或首段语音响应速度。

## 二、方案比较

| 方案 | 优点 | 问题 | 结论 |
| --- | --- | --- | --- |
| 前端按回复关键词猜测情绪 | 无需修改服务端 | 容易误判否定句、反讽和上下文情绪 | 不采用 |
| 仅按语音阶段切换动图 | 稳定、实现简单 | 只能表达聆听、思考、说话，无法准确表达高兴或伤心 | 作为基础状态层 |
| 服务端输出结构化情绪标签，前端叠加实时阶段 | 情绪准确，协议清晰，多端可复用 | 需要增加一个兼容字段及回退规则 | 推荐 |

## 三、角色与资产规范

- 唯一形象基准：`/Users/yuezhenting/esp/ygsoul-资源/动图/01_Speaking/hd_base.png`。
- 角色保持淡紫色细绒主体、黑色高光眼睛、粉色爱心和圆润手臂，禁止改变比例、配色、材质和配件。
- 每个状态只生成一套动图，不生成重复候选集。
- 画布固定为 `280×280`，透明背景，角色脚底、头顶和水平中心使用统一锚点。
- 每帧主体轮廓不得漂移；非动作区域尽量复用同一高清底图，避免全身闪烁。
- 不得出现棋盘格、白底、绿底、毛边、黑边、阴影地面、杂点和切割痕迹。
- 网页交付优先使用透明 APNG；GIF 只作为兼容预览，不作为高清主资源。
- 单状态采用少量关键帧和合理帧延时；浏览器按需预加载，禁止一次加载全部非必要大资源。

## 四、状态模型

### 4.1 实时阶段

| 页面阶段 | 动图状态 | 触发事件 |
| --- | --- | --- |
| `idle` | 待机 | 未通话或一轮结束 |
| `listening` | 聆听 | 麦克风和 VAD 已就绪 |
| `hearing` | 听到你了 | VAD 检测到有效人声 |
| `recognizing` | 听懂/思考 | 用户停止说话，等待最终识别 |
| `thinking` | 思考 | 大模型开始生成、尚未播放语音 |
| `speaking` | 说话 | 收到并播放首段 TTS 音频 |
| `error` | 担心 | 麦克风、网络或模型链路异常 |

### 4.2 情绪标签

第一版仅允许以下稳定枚举：

```text
neutral  happy  sad  comforting  surprised
```

- `neutral`：平静、普通回答。
- `happy`：高兴、祝贺、积极回应。
- `sad`：伤心、失落、共情悲伤。
- `comforting`：安慰、温柔陪伴。
- `surprised`：惊喜、惊讶。

未知标签必须回退为 `neutral`，不得把任意模型文本直接拼入资源路径。

## 五、协议与优先级

服务端在开始输出本轮文字时发送兼容事件：

```json
{
  "type": "assistant.emotion",
  "emotion": "happy"
}
```

前端使用“双层状态”决策：

1. 实时阶段具有最高优先级。正在聆听、识别、思考或说话时，必须先展示对应阶段动图。
2. 本轮 TTS 播放结束后，展示本轮情绪动图 `1200–1800ms`，随后回到待机或聆听。
3. 错误状态立即覆盖其他状态；恢复连接后回到聆听。
4. 未收到情绪事件、资源加载失败或旧服务端不支持该事件时，统一回退到 `neutral`，不得阻断对话。

服务端情绪判断属于模型路由层的结构化输出能力，语音会话运行时只透传标准事件，不依赖具体大模型厂商。Web、App 和智能硬件可复用相同枚举。

## 六、前端组件边界

| 模块 | 单一职责 |
| --- | --- |
| 角色资源清单 | 声明状态名称、资源地址、是否循环和回退资源 |
| 角色状态控制器 | 根据实时阶段和情绪标签选择唯一显示资源 |
| 角色视图 | 展示当前 APNG、处理淡入切换和加载失败 |
| 协议解析 | 解析 `assistant.emotion`，不直接操作 DOM |
| 资源预加载 | 首屏只加载待机、聆听和说话，其他状态空闲时加载 |

角色状态控制器不得直接访问麦克风、播放器或 WebSocket；现有语音状态机只提供输入状态，避免 UI 动画与语音核心链路耦合。

## 七、动图设计

| 动图 | 表情与动作 | 循环要求 |
| --- | --- | --- |
| 待机 | 自然呼吸、轻微眨眼，嘴巴闭合 | 平滑无限循环 |
| 聆听 | 眼睛专注，身体极轻前倾或耳侧微动 | 平滑无限循环 |
| 听到你了 | 眼睛亮起并轻微点头 | 短循环，可持续 |
| 思考 | 视线轻微上移、慢眨眼，身体不漂移 | 平滑无限循环 |
| 说话 | 仅嘴型轮播，主体保持高清固定 | 平滑无限循环 |
| 高兴 | 眼睛眯成弧线、笑嘴、爱心轻微起伏 | 1–2 次短循环 |
| 伤心 | 眼睛下垂、单颗泪珠、嘴角下垂 | 1–2 次短循环 |
| 安慰 | 温柔弯眼、抱紧爱心、轻微点头 | 1–2 次短循环 |
| 惊讶 | 圆眼、O 型嘴、身体轻微回弹 | 1–2 次短循环 |
| 担心 | 眉眼轻垂、短暂左右查看 | 短循环，可持续 |

## 八、性能和兼容性

- 动图切换不得阻塞音频线程、WebSocket 消息处理或 TTS 播放。
- 首屏必需角色资源应尽量控制在 `300KB` 内；情绪资源延迟加载并启用长缓存。
- 资源应带内容哈希或版本号，避免浏览器继续使用旧动图。
- 桌面 Chrome、Android Chrome 和微信 WebView 均需验证 APNG 播放；不支持时回退到透明静态首帧。
- 遵守 `prefers-reduced-motion`：系统减少动态效果时显示对应状态首帧。

## 九、验收标准

1. 页面不再出现 CSS 扁平企鹅，使用同一毛绒幽光形象。
2. 待机、聆听、听到你了、思考、说话、高兴、伤心、安慰、惊讶和担心均有唯一资源。
3. 动图画布、主体大小和位置一致，循环过程中无闪烁、抖动、漂移和切割边缘。
4. 所有资源透明且无背景杂质，角色轮廓保持细腻毛绒质感。
5. 通话状态严格跟随真实 VAD、ASR、大模型和 TTS 事件。
6. 每轮服务端情绪标签可在网页端正确显示；未知标签与旧服务端兼容回退。
7. 动图加载失败不影响拾音、语音识别、大模型回复、TTS 播放和打断。
8. 现有自动化测试全部通过；桌面 Chrome 与手机真机完成语音闭环回归。
9. 从用户说完到首段 TTS 播放仍以稳定低于 `1000ms` 为目标，动图接入不得引入可测量延迟回退。
