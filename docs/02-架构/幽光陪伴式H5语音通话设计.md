# 幽光陪伴式 H5 语音通话设计

> 状态：已确认，实施中  
> 日期：2026-08-29

## 一、目标

把当前工程测试页升级为可直接体验的幽光 AI 陪伴产品雏形，同时保留真实语音链路、延迟测量和故障诊断能力。用户可从聊天首页发起语音通话，进入类似豆包的免按键连续对话界面，直观验证响应速度、连续对话和打断效果。

## 二、体验结构

### 2.1 聊天首页

- 顶部展示幽光头像、名称和连接状态。
- 中部使用正常聊天气泡展示用户文字、识别结果和幽光回复。
- 聊天内容区独立滚动，底部文字输入和“开始语音通话”入口固定，不随消息数量移动或被消息遮挡。
- 用户消息、幽光增量回复和回复完成时均自动滚动至最新一条消息。
- 每条已经产生语音合成结果的幽光回复展示独立语音按钮，支持播放、暂停、继续和播放完成后重新播放。
- 网络、模型或麦克风异常以聊天消息提示，不暴露内部错误堆栈。
- 延迟、采样率和原始事件收进可收缩调试栏。桌面端使用聊天区与日志区左右分栏，日志展开时不得覆盖聊天；移动端使用不遮挡核心操作的纵向分栏。

### 2.2 实时语音通话页

- 使用全屏柔和紫粉渐变和轻量光晕，视觉重点为幽光形象。
- 顶部展示返回、名称、在线状态和通话时长。
- 中部展示幽光形象、当前状态和与状态同步的动态声波。
- 下部展示最近一轮用户字幕、幽光字幕和本轮首段语音响应耗时。
- 底部提供麦克风静音、文字入口、打断和挂断按钮。
- 手机端全屏优先；桌面端限制最大宽度，保持接近手机通话界面的视觉比例。

## 三、通话状态机

```text
未连接 → 连接中 → 准备麦克风 → 我在听 → 听到你了 → 正在听懂 → 想一想 → 幽光说话中
                                             ↑                         │
                                             └────── 用户插话打断 ──────┘

任意状态 → 网络异常/麦克风异常 → 可重试
任意通话状态 → 挂断 → 返回聊天首页
```

- `我在听`：麦克风已就绪，等待用户开口。
- `听到你了`：Silero VAD 已检测到有效人声并开始流式发送 PCM，不能仅靠定时动画进入。
- `正在听懂`：用户停止说话，等待阿里云 Paraformer Realtime v2 最终文字。
- `想一想`：阿里云通义千问 Qwen 3.7 Flash 已开始生成，尚未收到语音。
- `幽光说话中`：开始播放火山引擎 BigTTS v3 返回的 PCM 音频。
- 用户在幽光说话时开口，立即停止本地播放并向服务端发送打断。

## 四、交互与技术边界

- 页面只负责录音、播放、状态展示和协议收发，不实现模型业务逻辑。
- 服务端继续负责语音识别、大模型、语音合成、抢占式生成和打断。
- 免按键连续对话优先复用成熟浏览器端语音活动检测能力；不得在页面内自研复杂识别算法。
- 首期固定复用 `@ricky0123/vad-web 0.0.30`（Silero VAD + ONNX Runtime Web），加载失败时自动回退到现有按住说话方式，不阻断文字和手动语音验收。
- 现有 WebSocket 消息类型保持兼容，新增界面状态由既有事件映射产生。
- 详细诊断信息默认隐藏，产品界面不出现 Token、Provider、Frame 等内部术语。
- 调试日志采用可折叠分栏：桌面端固定在右侧并占据独立布局空间，移动端位于主内容下方；展开时不使用遮罩且不得遮挡聊天输入、挂断、静音、打断等核心操作。
- 调试抽屉按时间顺序展示连接、录音、语音识别、大模型、语音合成、播放和打断事件，支持自动滚动、复制与清空，所有密钥和敏感请求内容必须脱敏。
- 打断后丢弃旧一轮仍在网络途中的语音，直到收到该轮结束事件，防止旧音频串入下一轮。

## 五、错误处理

- 麦克风未授权：解释原因并提供重新授权按钮。
- 非安全上下文不支持录音：明确提示必须通过 HTTPS 访问。
- WebSocket 断开：通话页进入重连状态，重连失败允许返回聊天首页。
- 语音识别无结果：恢复聆听，不生成空回复。
- 模型或语音合成失败：停止等待动画，显示简洁错误并允许继续下一轮。
- 页面切入后台或挂断：停止麦克风、音频播放、定时器和 WebSocket 会话。

## 六、模块职责

| 模块 | 单一职责 |
| --- | --- |
| 连接控制 | 建立、重连和关闭 WebSocket，解析服务端事件 |
| 录音控制 | 麦克风授权、重采样、语音活动检测和 PCM 发送 |
| 播放控制 | PCM 排队播放、打断清空和播放结束 |
| 消息语音归档 | 按幽光回复收集对应 PCM，生成页面内临时 WAV，并控制该条消息的播放、暂停和继续 |
| 通话状态 | 将协议事件映射为通话状态，不操作底层音频 |
| 聊天消息 | 管理用户、幽光和系统消息的展示 |
| 调试面板 | 展示耗时、采样率和脱敏事件日志 |

首期保持单页零构建交付，但代码必须按以上职责分区；若页面继续增长，再拆成独立脚本和样式文件，不提前引入前端框架。

## 七、验收标准

1. 首页可以连接服务、发送文字并展示完整聊天气泡。
2. 点击“开始语音通话”可以进入全屏通话页并自动申请麦克风。
3. 用户无需按键即可完成“说话—停止—收到回答—继续说话”的连续闭环。
4. “我在听、听到你了、正在听懂、想一想、幽光说话中”与真实 VAD、ASR、大模型和 TTS 事件一致。
5. 幽光说话时用户插话，本地立即静音，旧音频不恢复播放。
6. 页面展示每轮“说完到首段语音”的真实耗时。
7. 文字输入、手动打断、麦克风静音、挂断和调试详情可用。
8. 调试详情默认收起，可展开、收起、自动滚动、复制和清空；桌面端为右侧独立分栏，移动端为底部独立分栏，不使用遮罩且日志不包含密钥等敏感信息。
9. 手机窄屏和桌面宽屏无横向溢出，主要按钮可点击且不被遮挡。
10. 控制台无未处理异常，现有自动化测试和真实 WebSocket 链路回归通过。
11. 聊天输入区始终固定；幽光增量回复和完成回复后自动滚动到最新消息。
12. 每条带 TTS 的幽光回复可以播放、暂停、继续，同一时间最多播放一条历史回复。
13. 真实浏览器中从用户说完到收到首段 TTS PCM 小于 `1000ms`。
