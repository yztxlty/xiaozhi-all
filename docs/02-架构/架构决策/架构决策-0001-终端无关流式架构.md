# 架构决策记录-0001：采用终端无关的统一流式语音架构

> 状态：已接受
> 日期：2026-08-28
> 决策范围：全平台实时语音

## 背景

旧系统按平台分别处理录音转文字，并在大语言模型完整回复后生成 MP3 和对象存储 URL。该方式无法满足 ESP32 真机低延迟、打断和未来多终端复用要求。

## 决策

建立统一 语音会话运行时；ESP32/T5 经 Device Realtime Gateway 接入，网页端/移动端 经 LiveKit RTC Gateway 接入，两者转换为统一 AudioFrame 和 会话Event。语音识别、大语言模型、语音合成均通过可流式、可取消的模型提供方契约调用。

## 备选方案

- 继续改造旧消息系统：业务耦合和文件式音频路径过重，拒绝。
- 全部终端统一使用 LiveKit：对低成本 MCU 的运行时和协议负担过高，拒绝。
- 以 ESP32 协议作为平台协议：会限制 网页端、移动端 和未来芯片，拒绝。
- 直接采用端到端语音大模型：现阶段在文本可控、记忆、安全、供应商切换方面风险较高，仅保留实验通道。

## 影响

- 收益：一套会话状态机、多终端复用、低延迟、可靠打断和模型提供方可替换。
- 代价：必须新建二进制协议、播放确认、取消树、性能基准和真机测试体系。
- 迁移：旧系统只通过兼容适配器迁移用户、角色和文本数据，不迁移实时语音实现。
- 回滚：MVP 可临时切换到半双工模式，但不能退回完整 MP3+TOS 作为默认路径。

## 验证

以 ESP32 真机完成 P95 首音、打断、弱网恢复、30 分钟长稳和旧音频隔离验收。
