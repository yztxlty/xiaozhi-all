# 架构决策记录-0002：将 Dify 接入为无状态大语言模型工作流提供方

> 状态：已替代
> 日期：2026-08-28
> 决策范围：大语言模型路由器、会话服务、Dify 工作流适配器

> 替代说明：真实 `chat` 项目使用 Dify Chatflow `POST /chat-messages`，不是纯 Workflow App `/workflows/run`。当前决策见[架构决策记录-0003](架构决策-0003-真实Dify-Chatflow与模块化实时语音运行时.md)。本文仅保留历史决策过程。

## 背景

`xiaozhi-all` 需要复用已经部署好的 Dify 服务完成提示词编排、模型调用、知识检索和受控工具流程，同时保持实时语音首音、打断、记忆一致性和供应商可替换能力。

旧系统把 Dify `conversation_id`、角色变量、记忆和模型选择直接混入聊天业务，并以普通 `POST` 等待响应后再迭代 SSE 内容。这会形成双重会话事实源、削弱真实流式效果，并可能在部分输出后重试时产生重复文本。

## 决策

1. Dify 作为 `services/model-router` 内的一个 LLM Provider Adapter 接入，不进入 Voice Session Runtime 和 Conversation Service 的核心接口。
2. Dify 使用 Workflow App 的流式接口，每轮执行独立的 `/v1/workflows/run`，不传递或保存 Dify `conversation_id`。
3. `xiaozhi-all` 是角色、短期上下文、长期记忆、Session、Turn、Generation 和实际播放历史的唯一事实源；每轮调用前由 Conversation Service 组装有界上下文。
4. Adapter 必须真实消费 SSE `text_chunk`，立即转换为统一 `llm.text.delta`，不能先缓存完整回复。
5. 用户打断时，Voice Session Runtime 取消 `generation_id`；Adapter 关闭本地 SSE，并以 `task_id` 调用 Dify Workflow Stop API。取消后的迟到事件全部丢弃。
6. Dify 是已经部署好的外部服务。本项目不建设、不部署、不扩缩容、不管理 Dify 的数据库、队列、执行进程、模型或运行环境。
7. Dify 不可用时由大语言模型路由器 按统一模型提供方策略降级；本项目不尝试管理或重启 Dify。

## 备选方案

- 让 Dify Chatflow 保存会话和记忆：会与 会话服务 形成双重事实源，难以保证被打断回复只保存实际听到内容，拒绝。
- 语音会话运行时 直接调用 Dify：会把供应商协议、密钥和错误语义耦合进实时会话核心，拒绝。
- 新建独立 Dify Bridge 微服务：当前没有独立部署、扩缩容或安全隔离需求，会增加一次网络跳转和运维面，MVP 拒绝。
- 绕过 Dify，仅直连 OpenAI-Compatible大语言模型：保留为主备模型提供方，但无法复用已部署 Dify 的工作流、知识和工具编排，不作为本决策的唯一方案。

## 影响

- 收益：Dify 可随时替换；会话与记忆一致；服务端事件流词元可直接进入流式语音合成；打断可向下传播；多终端共享同一模型提供方契约。
- 代价：需要维护 Dify服务端事件流事件映射、取消、超时、错误归一化和契约测试。
- 风险：Dify 工作流增加前置模型节点会拉高 首字延迟；普通陪聊必须保留无额外大语言模型分类的快速路径。
- 迁移：旧系统的 Dify 变量只作为字段来源参考，不迁移 `conversation_id`、重试逻辑或完整回复等待方式。
- 回滚：通过 LLM Router 配置禁用 `dify_workflow`，切换至 OpenAI-Compatible Provider；不改变设备协议、会话状态机和历史数据结构。

## 验证

- 契约测试覆盖 `ping`、`workflow_started`、`text_chunk`、`workflow_finished`、`error`、失败节点、断流和未知事件。
- 验证首个 `text_chunk` 到达后立即产生统一 delta，不等待 `workflow_finished`。
- 验证打断后 Dify Stop API 被调用，且旧 `generation_id` 的迟到文本不会进入 TTS、历史或记忆。
- 以至少 100 个有效轮次 统计 Dify 大语言模型首字延迟，并纳入全链路 P95 首音 1.2 秒和打断 250 毫秒门禁。
- 验证 Dify 接口密钥 仅存在于服务端密钥配置，日志、链路追踪、设备、网页端和移动端 均不包含密钥。
