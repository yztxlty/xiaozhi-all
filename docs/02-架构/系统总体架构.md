# 系统总体架构

> 状态：基线生效
> 版本：v0.1
> 更新日期：2026-08-28
> 架构决策记录：架构决策记录-0001

## 架构目标

以统一实时会话运行时承载所有终端，把终端传输、模型提供方和业务控制面解耦，使 ESP32 首轮低延迟验收不会限制未来 T5、网页端、移动端和新应用扩展。

## 逻辑架构

```text
ESP32 / T5 / 其他硬件 ── 设备实时网关 ─┐
                                      ├─ 语音会话运行时
网页端 / 移动端 ──────── 实时通信网关 ─┘       │
                                                 ├─ 轮次引擎
                                                 ├─ 语音识别路由器
                                                 ├─ 大语言模型路由器
                                                 ├─ 语音合成路由器
                                                 └─ 播放协调器

控制接口 ── 用户 / 设备 / 角色 / 记忆 / 配置 / 计费 / 空中升级
可观测平台 ── 链路追踪 / 指标 / 日志 / 成本 / 质量
```

## 模块责任

| 模块 | 责任 | 不承担 |
| --- | --- | --- |
| 设备实时网关 | 设备鉴权、二进制帧、心跳、网络恢复、协议适配 | 语音识别、大语言模型和语音合成业务规则 |
| 实时通信网关 | 网页端、移动端 WebRTC 接入和媒体转发 | 角色、记忆和模型路由 |
| 语音会话运行时 | 状态机、轮次、取消、背压、事件编排 | 终端专属用户界面 |
| 轮次引擎 | 语音活动检测、智能轮次、真实打断和误打断判断 | 文本内容生成 |
| 模型提供方路由器 | 主备选择、超时、熔断、能力校验、成本记录 | 业务计费规则 |
| 会话服务 | 角色、上下文、已听内容、记忆提交 | 原始音频长期保存 |
| 控制接口 | 用户、设备、配置、权限、计费、应用管理 | 实时音频搬运 |

## 数据原则

- 原始音频默认仅在会话内短暂存在，不作为聊天记录长期保存。
- 对话历史保存最终用户文本和用户实际听到的 AI 文本。
- 所有事件使用 `session_id + turn_id + generation_id` 关联。
- 模型提供方凭证只存在于服务端密钥系统。
- 音乐、设置、小游戏通过应用服务和资源仲裁接入，不能直接控制实时模型管线。

## 部署起点

最小可行版本使用模块化单体控制接口，加独立设备实时网关和语音会话运行时进程；数据库、Redis、对象存储和指标系统作为基础设施。只有通过压测证明存在独立扩缩容需求时再拆分更多服务。
