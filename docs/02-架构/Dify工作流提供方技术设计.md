# Dify 工作流模型提供方技术设计

> 状态：草案（未来纯 Workflow App 可选 Provider，非当前 MVP 基线）
> 版本：v0.1
> 更新日期：2026-08-28
> 责任模块：大语言模型路由器、会话服务
> 架构决策记录：0002

> 当前真实 `chat` 项目使用 Dify Chatflow 的 `POST /chat-messages`，ESP32 最小闭环必须以[最小化实时语音全链路实施方案](最小化实时语音全链路实施方案.md)为准。只有部署独立纯 Workflow App 后，本文档才可重新进入评审。

## 背景与目标

以已经部署好的 Dify 工作流服务作为可替换的大语言模型提供方，为智能硬件、网页端和移动端提供统一、低延迟、可取消的文本生成能力。设计必须满足真实服务端事件流输出、用户打断、上下文一致性、提供方降级和可观测要求。

## 范围与非目标

### 范围

- Dify 工作流适配器的模块边界、调用链和配置。
- 会话服务到大语言模型提供方的上下文交付。
- Dify服务端事件流事件到统一大语言模型事件的映射。
- 取消、超时、重试、降级、指标和安全规则。
- 普通陪聊、知识问答和受控工具任务的 Dify 工作流结构。

### 非目标

- 不部署、升级、扩缩容或运维 Dify 服务。
- 不由 Dify 保存对话历史、角色状态或长期记忆。
- 不使用 Dify 的语音识别或语音合成能力替代实时语音主链路。
- 不把 Dify 接口密钥下发至设备、网页端或移动端。
- 不实现 Dify 管理后台、工作流设计器或模型安装功能。

## 系统边界

```text
ESP32 / T5 / 网页端 / 移动端
          │
          ▼
语音会话运行时
          │大语言模型请求 + 取消信号
          ▼
大语言模型路由器
          │
          ├── 兼容 OpenAI 接口的模型提供方
          └── Dify 工作流适配器
                    │ HTTPS +服务端事件流
                    ▼
              已部署的 Dify 服务

会话服务 ── 角色 / 短期上下文 / 长期记忆 ──►大语言模型路由器
```

### 责任划分

| 模块 | 负责 | 不负责 |
| --- | --- | --- |
| 会话服务 | 角色、上下文裁剪、记忆召回、实际听到文本提交 | Dify 网络协议 |
| 语音会话运行时 | 轮次、生成任务、取消树、语音合成编排、播放确认 | Dify 接口与工作流节点 |
| 大语言模型路由器 | 模型提供方选择、健康检查、超时、熔断、降级 | 业务记忆存储 |
| Dify 工作流适配器 | 输入映射、服务端事件流解析、事件归一化、停止任务 | 保存会话或管理 Dify 服务 |
| 已部署的 Dify 服务 | 提示词、模型、知识和工具工作流执行 | 终端协议和实际播放历史 |

## 正常调用时序

```text
语音识别最终结果
  │
  ├─► 会话服务：组装角色、短期历史、长期记忆
  │
  └─►大语言模型路由器：创建生成任务并选择 Dify 工作流提供方
          │
          └─► 发起流式工作流请求
                  │
                  ├─ 工作流启动：保存任务标识和运行标识
                  ├─ 文本增量：立即输出统一文本增量事件
                  └─ 工作流完成：输出用量和结束原因
                          │
                          └─► 语义分句器 ► 流式语音合成► 终端播放
```

第一段 `text_chunk` 到达后必须立即向下游发布，不等待结束节点或完整输出。

## Dify 工作流设计

### 普通陪聊快速路径

```text
开始 → 输入校验 → 条件场景分支 → 低延迟大语言模型→ 流式文本输出 → 结束
```

- `scene=companion_chat` 直接进入大语言模型，不增加问题分类模型、摘要模型或智能体循环。
- 提示词使用外部传入的角色、短期上下文和长期记忆，不读取 Dify 会话变量。
- 输出采用自然口语，默认避免复杂标记格式、链接朗读和冗长列表。

### 知识问答路径

```text
开始 → 输入校验 → 知识检索 →大语言模型→ 流式文本输出 → 结束
```

仅当上游明确传入 `scene=knowledge_qa` 时进入检索，不使用额外大语言模型对每轮陪聊进行分类。

### 受控工具路径

```text
开始 → 输入校验 → 工具网关 → 结果校验 →大语言模型→ 流式文本输出 → 结束
```

- 有外部副作用的工具必须经过 `xiaozhi-all` 工具网关，并携带稳定幂等键。
- Dify 不直接持有设备控制权限、用户管理权限或业务数据库凭证。
- 工具失败必须返回可解释结果，不允许工作流无限重试。

## 上下文与记忆

### 唯一事实源

```text
会话服务
├── 最终用户文本
├── 用户实际听到的人工智能回复文本
├── 角色与关系状态
├── 短期历史
├── 长期记忆召回
└── 候选记忆提交

Dify 工作流
└── 只读取本轮传入的有界上下文
```

- 每轮均为独立工作流运行，不发送 `conversation_id`。
- 短期历史最多 8 个轮次，并限制在 4,000 个输入词元内。
- 长期记忆最多 8 条，并限制在 1,500 个输入词元内。
- 角色和策略限制在 1,500 个输入词元内。
- 用户本轮文本限制在 1,000 个输入词元内。
- 全部输入总预算不超过 8,000 个词元；超出时依次裁剪最旧短期历史、低相关长期记忆和角色非核心描述。
- 被取消生成任务产生的文本不提交为历史或记忆。

## 流式事件处理

适配器按照 [Dify 工作流模型提供方契约](../03-协议/Dify工作流提供方契约.md)处理服务端事件流：

- 跳过空行和 `event: ping`。
- `workflow_started` 保存 `task_id` 和 `workflow_run_id`。
- `text_chunk` 转换为有序 `llm.text.delta`。
- `reasoning_chunk` 不下发、不进入语音合成、不记录内容，仅统计事件数量和耗时。
- `workflow_finished.status=succeeded` 转换为 `llm.completed`。
- 失败状态或 `error` 转换为统一 `llm.failed`。
- `workflow_paused` 和人工输入节点在实时语音路径不受支持，按配置错误处理。
- 未识别事件只记录事件类型，不中断已知协议处理。

## 用户打断与取消

```text
用户开始说话
  │
  └─ 语音运行时取消生成任务
       ├─ 立即停止语音合成、下行队列和终端播放
       ├─ 标记生成任务为已取消
       ├─适配器关闭服务端事件流消费
       └─ 调用 Dify 工作流停止接口
```

- 本地取消不依赖 Dify 停止接口成功；生成任务一旦取消，迟到事件立即丢弃。
- 尚未收到 `task_id` 时先关闭请求；收到后进行一次尽力停止。
- 停止接口使用与启动请求相同的匿名 `user`。
- 停止请求使用独立的 500 毫秒超时期限，不阻塞语音运行时的播放停止。

## 超时、重试与降级

| 场景 | 适配器行为 | 是否可切换备用模型提供方 |
| --- | --- | --- |
| 连接失败且尚无文本增量 | 最多重试一次，随机退避 50～100 毫秒 | 可 |
| HTTP 429、502、503 或 504，且尚无文本增量 | 最多重试一次 | 可 |
| HTTP 400、401、403 或 404 | 不重试，标记配置或权限错误 | 可，由路由策略决定 |
| 服务端事件流中途断开且已有文本增量 | 不原地重试，不拼接第二次回复 | 不自动切换 |
| 工作流节点失败 | 转换为统一失败事件 | 仅在尚无文本增量时可切换 |
| 用户取消 | 停止本地消费并调用停止接口 | 不切换 |

默认超时期限：连接 1 秒、读取空闲 15 秒、单轮总生成 20 秒、停止请求 500 毫秒。任何重试都沿用原 `session_id/turn_id`，但备用模型提供方必须使用新的 `generation_id`。

## 配置

| 配置项 | 含义 | 是否敏感 |
| --- | --- | --- |
| `DIFY_WORKFLOW_BASE_URL` | 已部署 Dify 服务接口基地址，包含 `/v1` | 否 |
| `DIFY_WORKFLOW_API_KEY` | 工作流应用接口密钥 | 是 |
| `DIFY_WORKFLOW_PROVIDER_ID` | 模型提供方实例标识，默认 `dify-workflow-primary` | 否 |
| `DIFY_WORKFLOW_CONNECT_TIMEOUT_MS` | 连接超时，默认 1000 | 否 |
| `DIFY_WORKFLOW_READ_TIMEOUT_MS` | 服务端事件流读取空闲超时，默认 15000 | 否 |
| `DIFY_WORKFLOW_TOTAL_TIMEOUT_MS` | 单轮总超时，默认 20000 | 否 |
| `DIFY_WORKFLOW_STOP_TIMEOUT_MS` | 停止请求超时，默认 500 | 否 |
| `DIFY_WORKFLOW_MAX_RETRIES_BEFORE_DELTA` | 首个文本增量前最大重试次数，固定为 1 | 否 |

接口密钥必须由服务端密钥系统注入，禁止写入仓库、镜像层、日志、链路追踪或错误响应。

## 可观测性

每轮记录：

- `session_id`、`turn_id`、`generation_id` 和模型提供方标识。
- Dify `task_id`、`workflow_run_id`，仅作为内部追踪字段。
- 请求开始、首个 `text_chunk`、完成、取消和失败时间。
- 首字延迟、总耗时、文本增量数、输入输出词元、工作流状态和错误码。
- 重试、降级、停止接口发起与结果。

禁止记录提示词全文、角色隐私、长期记忆正文、鉴权请求头和 `reasoning_chunk` 内容。

## 异常、风险与回滚

- 工作流前置节点过多：普通陪聊走最短路径，并以首字延迟指标阻断发布。
- Dify 发布版本发生行为漂移：每次发布必须执行契约测试和一百轮延迟回归，并记录发布时间和验证结果。
- 部分输出后断流：终止当前生成任务，不把新请求内容拼接到旧回复。
- Dify 故障：大语言模型路由器在首个文本增量前切换备用模型提供方。
- 适配器回滚：禁用 Dify模型提供方配置并恢复兼容 OpenAI 接口的模型提供方，不修改设备和会话协议。

## 验收标准

1. Dify 每轮请求不包含 `conversation_id`，服务重启后可由同一输入独立执行。
2. 首个 `text_chunk` 在同一事件循环周期内转换为 `llm.text.delta`。
3. 100 个有效轮次的大语言模型首字延迟 P95 不高于 450 毫秒；实测不达标时不得作为 ESP32 默认主模型提供方。
4. 打断到设备停止播放 P95 不高于 250 毫秒，停止接口不得阻塞本地停止。
5. 取消后没有旧生成任务文本进入语音合成、历史或记忆。
6. 所有 Dify 已知服务端事件流事件、失败状态、断流和未知事件均有契约测试。
7. 首个文本增量前故障可按路由策略降级，首个文本增量后不得自动拼接备用回复。
8. 日志、链路追踪、测试夹具和仓库扫描均不包含真实 Dify 接口密钥或用户隐私正文。
