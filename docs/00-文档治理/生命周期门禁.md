# 项目生命周期与阶段门禁

> 状态：基线生效
> 版本：v0.1
> 更新日期：2026-08-28

| 门禁 | 阶段 | 必须具备的证据 | 禁止进入下一阶段的条件 |
| --- | --- | --- | --- |
| G0 | 立项 | 愿景、用户、范围、非目标、成功指标 | 目标依赖具体芯片或单一云厂商 |
| G1 | 需求基线 | 功能需求、非功能需求、验收指标、优先级 | 指标不可测或终端边界不清 |
| G2 | 架构基线 | 架构图、模块责任、架构决策记录、安全与容量初判 | 控制面和实时数据面混杂 |
| G3 | 协议冻结 | 版本、事件、状态机、错误码、兼容和取消语义 | 无法区分会话、轮次和生成代次 |
| G4 | 开发完成 | 测试驱动开发 证据、评审、构建、静态检查、依赖清单 | 存在未解释失败或敏感信息 |
| G5 | 验收完成 | 自动化、弱网、长稳、真机、回归与性能报告 | 仅模拟器通过或只测成功路径 |
| G6 | 发布批准 | 版本说明、迁移、回滚、监控、值守安排 | 无回滚方案或核心指标不可观测 |
| G7 | 运营复盘 | 服务等级目标、成本、故障、用户反馈、改进项 | 问题无责任模块或无关闭证据 |
| G8 | 退役 | 替代方案、数据处理、兼容期和通知记录 | 仍有活跃终端依赖旧协议 |

## 强制原则

- ESP32 首轮验证必须走真机，模拟器不能替代 G5。
- 新终端只新增 Transport适配器，不复制一套会话、语音识别、大语言模型、语音合成业务链。
- 协议和模型提供方均必须支持取消、超时、幂等、背压和可观测事件。
- 任何架构变更先记录 架构决策记录，再实施。
