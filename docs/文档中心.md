## 文档状态

- `草案`：可讨论，不能作为实现依据。
- `评审中`：边界已明确，等待相关责任人确认。
- `基线生效`：当前实现、测试和验收必须遵循。
- `已替代`：必须链接到新的文档或架构决策记录。
- `已归档`：仅保留历史，不得继续引用为当前规范。

## 变更规则

1. 需求变化先修改需求基线；架构变化必须新增或替代架构决策记录。
2. 协议字段变化必须说明兼容方式、版本号、迁移和回滚策略。
3. 性能结论必须附测试环境、音频样本、统计口径和原始结果位置。
4. 禁止在文档中记录接口密钥、访问令牌、证书私钥、用户音频或真实个人数据。
5. 发布前必须同步需求、架构决策记录、协议、验收报告、发布记录和已知问题。

详细规则见[文档治理规范](00-文档治理/文档治理规范.md)和[生命周期与阶段门禁](00-文档治理/生命周期门禁.md)。
